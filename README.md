# Majik Maker

[Open the app](https://asciikat.github.io/majikmaker/)

An installable web app for phone and desktop. Turn an intention into a simple sigil with **at most five pen strokes**, follow a step-by-step drawing guide, or explore a sourced historical-symbol library. Images are optional. Export as a 1600 × 1600 PNG or SVG, with black ink on white paper by default. On supported phones, “Save image” opens the native file-sharing sheet.

## Words, will and historical symbols

**Crowley-inspired intentions:** Aleister Crowley describes magick in terms of will and deliberate action. In *Liber O*, chosen symbols and ritual objects reinforce an idea as a system of mnemonics. His correspondences belong to his particular ceremonial tradition.

**Spare-inspired word sigils:** Austin Osman Spare’s *The Book of Pleasure* (1913) describes combining simplified alphabet letters into a form that is easy to visualize. Our app applies a contemporary recipe: normalize accents, keep each A–Z letter once, reduce letter forms to stems, bars, angles, curves and loops, and overlap these shared shapes. Deduplication and this five-shape alphabet are our design choices, not instructions claimed to come directly from Crowley or Spare. The seed chooses a simple arrangement; different intentions can share forms. Word mode requires at least one A–Z letter; historical mode supports intentions in any script.

**Historical mode:** a curated, expanding collection of documented marks. Each entry names its tradition, period, contextual meaning, source and drawing steps. Selection preserves the catalogued form rather than combining it into an invented “ancient” mark. These are simplified vector renderings of conventional glyphs, not facsimiles of manuscripts, and historical forms vary. The library does not claim to contain every symbol from every culture.

**Geometric art:** the original Orbital, Resonance and Entangled styles remain available as optional decorative art. An image’s sampled pixels can alter personal word-sigil arrangements and geometric patterns; an image never changes a selected historical glyph.

Use the app for reflection, visualization and remembering goals. Historical practice does not establish guaranteed supernatural outcomes, and quantum physics does not establish that thoughts or symbols manifest objects.

Primary-text transcriptions consulted:

- [Crowley, *Magick in Theory and Practice*, Introduction](https://github.com/jonnyg23/mahabrain/blob/main/sacred_obsidian_vault/oto/aba/defs.md)
- [Crowley, *Liber O*, especially I.2–3 and II.2–5](https://github.com/jonnyg23/mahabrain/blob/main/sacred_obsidian_vault/oto/libero.md)

## Run locally

Install Node.js 20 or later, then run:

```sh
npm start
```

Open `http://127.0.0.1:4173`. No dependency installation, build, API key, or backend is required. Opening `index.html` directly allows basic editing, but installation, service workers, and the example photo require the local server or an HTTPS host.

## Install on phone or desktop

Open the hosted HTTPS app and select **Install app** for instructions.

- **iPhone / iPad:** open in Safari → Share → Add to Home Screen.
- **Android:** open in Chrome → Install app / Add to Home screen.
- **Windows / Linux / macOS:** use Chrome or Edge’s install option.
- **macOS Sonoma or later:** Safari → File → Add to Dock.

This is a progressive web app (PWA), rather than an App Store package. It launches in its own window where the browser supports installation. After one successful online visit completes the service-worker cache, the app can reopen and generate symbols offline. Device photos, intentions, and generated symbols remain in memory and clear when the app is closed or refreshed; download anything you want to keep. No photo is uploaded or automatically saved.

## Deploy to GitHub Pages

The app’s `index.html` and assets live at the repository root, so **Deploy from a branch → main → / (root)** works directly. A `.nojekyll` file keeps the app static and prevents README rendering from replacing it.

The included GitHub Actions workflow also builds the public app into `dist/` and publishes it. It works when **GitHub Actions** is the selected Pages source. Both publishing paths serve the same app.

Relative paths allow deployment at `/majikmaker/` or at a domain root. Once Pages reports a successful deployment, use its displayed URL to open and install the app. Other static HTTPS hosts can serve the output of `npm run build` from `dist/`.

## Development

```sh
npm run check
npm test
```

`symbol.js` contains the word drawing recipe, historical rendering and deterministic geometric generator. `catalog.js` contains the sourced historical marks and stroke guides. `app.js` handles browser-only image processing and exports. `install.js` handles install prompts and device instructions. `sw.js` caches the app shell and local assets. Bump `CACHE_NAME` in `sw.js` and the matching version query on CSS/JS references and precache URLs whenever shipped code changes. This keeps returning installations from combining new HTML with old cached code.

Automated checks cover simple stroke limits, letter contributions, historical form preservation, catalog metadata, symbol determinism and variation, SVG integrity, service-worker install/activation/fetch behavior, scoped offline navigation, asset completeness, and manifest paths. The GitHub Actions browser check verifies the built app under the GitHub Pages `/majikmaker/` path, desktop and phone layouts (320–1440 px), word-only generation, historical search and selection, drawing guides, optional image upload, paper PNG/SVG exports, dialogs, and offline reload/generation. It saves desktop and phone previews as an Actions artifact. Publishing also checks that the live Pages URL serves the app and its current service worker. Native installation and iOS file sharing still need verification on real devices.

The bundled dream-home image is an AI-generated example, not a photo of an identified property.
